hetero-serve Featured

CUDA • C++ • WMMA / tensor cores • Nsight Compute • PyTorch • NumPy • paged attention • NCCL • asyncio • Docker

A prefix fills, the next request reuses it instead of recomputing, then the cache crosses the interconnect — drive it yourself in the browser →

A KV-cache-aware LLM serving scheduler with hand-written CUDA paged-attention kernels. When a request shares a long prefix with an earlier one — a system prompt, a RAG document, an earlier turn — its KV cache already exists, but often on the wrong accelerator. You can run it where the cache is and wait behind a busy device, recompute the prefix, or drag the cache across the interconnect. That third option is a bandwidth-versus-compute trade, and this system is built to find where it flips.

55.4%of a Tesla T4's peak memory bandwidth
10–22×faster than PyTorch SDPA on paged KV
3.60s → 1.94send-to-end p50 from cache-aware routing
101tests, no mocks, real processes and sockets
  • Paged KV cache with 16-token blocks, refcounts, chain-hashed prefix sharing and LRU eviction; continuous batching with chunked prefill and recompute-preemption.
  • A cost model that measures instead of assuming — it prices stay against migrate in seconds using per-device speeds probed at startup. Workers are real OS processes talking over real TCP through a token-bucket shaper, so concurrent transfers genuinely contend.
  • Five CUDA kernels, each written in response to a measurement. Profiling showed a third of every decode step was the host gathering KV blocks into contiguous tensors — overhead invented by paging. v1 fuses that away; v2 adds FlashAttention-style online softmax; Nsight then showed v2 was occupancy-starved rather than bandwidth-starved (0.1 waves across 40 SMs), producing v3's context split — 13.4% → 55.4% of peak.
  • A prefill kernel and a tensor-core version, where a 16-token KV page is exactly one 16×16×16 WMMA fragment — which is why that block size was the right default before any kernel existed.
  • Grouped-query attention moves the answer: Llama-3's 4:1 ratio shrinks the cache 4× and drops the migration crossover from 503 Mbps to 126 Mbps — from needing a datacenter fabric to working on commodity networking.
  • Five bugs documented, every one found by measuring rather than reading — including one where I was confident the cause was a serialisation layout, benchmarked it first, and was wrong.

The router decides where; each worker decides when.
